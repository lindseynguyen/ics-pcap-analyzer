# Sample captures

Small **synthetic** captures for trying the analyzer without real plant traffic.
They are generated by [`tests/pcap_factory.py`](../tests/pcap_factory.py) and contain
only made-up addresses (`192.168.10.0/24`, `203.0.113.0/24`), so they are safe to share.

| File | Size | What is in it | Expected result |
|---|---|---|---|
| `benign_plant.pcap` | 29 KB | One minute of normal plant traffic: Modbus polling, S7 reads, DNP3, IEC 104, OPC UA, MQTT, DNS, HMI web | **0 anomalies** (false-positive baseline) |
| `ot_protocols.pcap` | 3 KB | One example of each supported OT protocol (Modbus, S7comm, DNP3, EtherNet/IP, IEC 104, OPC UA, MQTT, BACnet) | All 8 protocols decoded |
| `attack_scenarios.pcap` | 475 KB | Port scan, brute force, Modbus write storm and replay, S7 PLC stop / program download, DNP3 restart, C2 beaconing, DNS tunnelling, web attacks on the HMI | ~29 anomalies, 1 **critical** attack chain |

## Try it

```bash
python -m ot_pcap_analyzer --cli samples/attack_scenarios.pcap --advanced -o report.xlsx
python -m ot_pcap_analyzer --cli samples/benign_plant.pcap      # should report no anomalies
```

Or open any file from the GUI (`python -m ot_pcap_analyzer`).

## Regenerate

```bash
pip install -r requirements-dev.txt
python scripts/generate_samples.py
```

Generation is deterministic: the same code produces byte-identical files, and the
test suite fails if the committed samples drift from the factory.

## Contributing real captures

Sanitised captures from real OT environments are the most useful contribution to
this project. Please **remove or rewrite IP/MAC addresses, hostnames and any
process values** before sharing, and open an issue first — see
[CONTRIBUTING.md](../CONTRIBUTING.md).
